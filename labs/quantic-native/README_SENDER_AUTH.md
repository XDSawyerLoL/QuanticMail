# Native hybrid sender authentication (lab)
PQ broker accepts one additional required argument: owner-only local JSON contact directory (1-32 exact address/device entries, public signing DER SPKIs in standard base64, expires epoch ms in next 24 h). The directory is explicitly provisioned by a trusted operator, not learned from an inbound message; no live sender authority/rotation/revocation is claimed. Each hybrid open requires senderAuth with raw P-256 r||s and ML-DSA-65 signatures in canonical unpadded base64url. Both sign the same domain-separated JSON array of exact sender, recipient, device IDs, message ID, suite, mode, ephemeral P-256 coordinates, KEM ciphertext, IV and AES ciphertext. Native verifier checks both signatures before consent or decryption, denies unknown/expired contacts, rechecks expiry after consent, and retains receiver replay/quorum gate. Existing unsigned native PQ envelope intentionally no longer opens in this mode. Test sender uses independent Python P-256/OpenSSL ML-DSA signing with synthetic keys; native sending and production integration not implemented. Contact directory freshness is limited by local time, not signed distributed revocation; restart required for local changes. No production deployment. CI pending.
