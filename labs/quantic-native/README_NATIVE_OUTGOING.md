# Native authenticated outgoing envelopes (lab)
The PQ-only broker accepts mail-seal-hybrid-lab, exact own sender identity/device, bounded JSON plaintext, and exact local independently provisioned recipient with optional classicalEncryptionSpki and mlKemEncryptionSpki. Recipient P-256 public point must derive the stated device ID. OpenSSL validates ML-KEM-768 public key and encapsulates; Go generates ephemeral P-256, derives the established hybrid HKDF key and AES-GCM ciphertext, and signs the established sender transcript with the local P-256 device key and ML-DSA device key. Requires explicit terminal approval (recipient and content hash, not trusted content preview) and durable fresh own-device quorum before any ciphertext/signatures leave. Reusing outgoing clientMessageId is denied even when content changes. No generic signing oracle or arbitrary caller-supplied encryption keys/envelope. No actual transmission, outbox retry/recovery, receiver distributed authorization, or production sender/recipient revocation yet. The directory is trusted local provisioning, not an independently verified distributed profile. Tests use an independent recipient with real Python ECDH/AES and OpenSSL decapsulation and signature verification. CI pending.
