# QCP2 two-contact snapshot lab
QCP2 uses 14336-byte responses and 256-byte requests; two compact binary proof slots of 4480 bytes, each with bounded JSON payload and raw P-256/ML-DSA signatures. The worker validates both grants atomically, current snapshot map must match exact durable contact payload. Quorum now requires matching contact permission sequence and digest, in addition to key commitment; expiry bounded by contact validity. Duplicate IDs, overflow, malformed slots, old QCP1 frames refused. Existing QCP1 witness DB requires separate explicit migration/provisioning; do not reset any production DB. Historical software downgrade is not prevented by current-code checks. Test exercises two independent contacts, revokes first at 3 witnesses and sends successfully to second. CI pending. Capacity remains deliberately limited to two contacts per vault, not production multi-user scale; contacts and roots still independently provisioned, remote peer revocation and real account linking remain open.
