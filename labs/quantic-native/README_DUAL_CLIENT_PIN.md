# Dual authority client gate
The PQ broker command now requires one additional independent SHA256 pin of the ML-DSA root SPKI. It refuses startup without it. Each vote must commit to the exact active grant, canonical address, device, two PQ key pins, sequence and pinned root. Matching but arbitrary digests are insufficient. Both signatures are still verified by the witnesses, not directly by the client; assumes trusted witness quorum and independently provisioned root pin. No live proof transfer or account migration. The test harness checks old argument list rejection and wrong root rejection, then executes the existing real dual-authority network scenario. The old mono-authority test now explicitly checks startup refusal. Source inventory updated to exact bytes. No changes to existing production client.
