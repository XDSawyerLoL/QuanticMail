# Native isolation RC2 — laboratory
The separate RC2 archive includes the compiled Windows and Linux Go programs, full sources, manual Windows hardware acceptance test, and 34 passing local tests (10 Go, 10 Python IPC, 14 Node, including 5 new dual-ownership tests using two real synthetic Linux child processes). The dual enrollment module now requires a fresh encrypted challenge response as well as the existing transcript signing proof; the trusted controller is assumed to hold the challenge, and the module has no production caller. It is not hardware attestation. Source blob 902dbf0900f09ad491690b5b17edd43f9ee9c6a0. Archive SHA256 42ba07d3a6c1f4be328af4079b040e4733246bfd53c8e2c48007604d2834361a.
The new Windows mode explicitly provisions two separate persistent P-256 lab keys using Microsoft Platform Crypto Provider, reopens without overwriting, verifies external public pins, rejects private export sizing and software fallback, requires a local confirmation dialog for private operations, checks CNG ECDH interoperability. Cross-compilation and Windows go vet succeed; real TPM runtime is unverified. CNG ECDH raw secret may be unsupported. The shared secret and AES operation remain in process memory. Local MessageBox is not secure desktop, trusted app authentication, or protection against a compromised OS; IPC parent sees plaintext. Replay cache is process-local and persistent keys now make cross-restart replay possible. Durable replay, authenticated sender, app authorization, current durable authority, migration (including historical keys/PQC), and native signed release remain blockers. No production identity touched, no IndexedDB copies removed, no deployment. Go source and subprocess integration tests are in the archive, not committed to the PR.
