# Experimental Windows PQ broker and recovery
The explicit Windows-only --broker-windows-pq-quorum-lab command accepts: directory, controller public key, classical signing pin, classical encryption pin, canonical address, device ID, ML-KEM pin, ML-DSA pin, independently provisioned PQ root pin. Requires a local attached console, both passwords, a private NTFS directory with existing classical.vault, pq.vault, journal.log, quorum.json and contacts.json. The quorum configuration's absolute TLS CA/certificate/private-key paths must point directly into the same private directory and pass native handle ACL checks. These inputs need separate trusted provisioning; no production importer is provided. Uses existing 3-of-4 distinct mTLS witnesses and fresh dual-signed proof retrieval, binds the same checkpoint ID and PQ profile, refuses missing/invalid proof or quorum before authenticating controller frames. Uses the existing PQ-only broker, mandatory per-contact fresh checks and durable checkpoint CAS. Recovery cache uses existing AEAD and request binding through exclusive write-through NTFS handles. Tests cover exact encrypted recovery after reopen, wrong request, overwrite and tamper refusal, missing/empty quorum. Windows end-to-end remote witness and desktop execution remain unverified. No proof of sudden power-loss durability: a missing cache or mismatch must fail closed. Direct authority HTTPS still exposes traffic timing; not routed via Scattering. No installer, migration or production enablement.
