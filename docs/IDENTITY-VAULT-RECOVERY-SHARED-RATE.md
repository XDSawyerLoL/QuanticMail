# Identity Vault / shared authentication budget (draft)

New encrypted backup format v2 records and checks the exact canonical address and fingerprint. Old v1 files require a separately known original canonical address because the same signing key can correspond to either the historic 10-hex address or the 32-hex address. Old readers reject v2 rather than silently downgrade it. Secondary devices cannot export a root backup. Recovery uses an atomic IndexedDB add operation and refuses to replace an identity in a concurrent tab. This does not isolate root keys from the web. No real identity has been migrated.

PostgreSQL-backed coarse authentication circuit breaker: opt-in QUANTIC_SHARED_AUTH_RATE_LIMIT=1 on the standalone PostgreSQL relay, or supply authRateLimiter to embedded relay persistence. Six fixed POST paths, fixed 60s database-clock windows, atomic conditional UPSERT, no untrusted forwarding headers, no client-created counter keys, no process-local fallback. It limits aggregate attempts across instances sharing the same database. A malicious client can exhaust the shared budget and deny legitimate registration; fixed window boundary bursts also remain. This is not per-device rate limiting, is not active on MySQL/Next-only routes, and does not protect transport ingress or all APIs. A real staging load test, identity/device keyed budgets with a bounded key lifecycle, trusted network attribution, and explicit availability policy are required. Tests include a disposable PostgreSQL CI service (two independent connection pools and restart). Do not set the test DB URL to a production database.

Native migration remains blocked on physical TPM and trusted native UI; never replace root public key, delete the browser root, or export an existing private key through a remote web origin. Hardware enrollment proof, recovery rehearsal, remote manifest/revocation convergence, and real native account flow must be separately validated. No production deployment.
