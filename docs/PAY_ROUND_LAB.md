# Experimental single-height view change

Separate synthetic protocol domain. Four fixed hybrid authorities; threshold three; at most one Byzantine authority; authenticated messages, fixed membership, and honest no-rollback state assumed. Two illustrative values only, not actual wallet transactions. This is an executable model, not a complete or proven production BFT implementation.

Prepare votes do not settle a transfer. A prepare certificate needs three hybrid votes in the same round. A commit vote requires a locally approved prepare and a verified prepare certificate; the authority retains that certificate while emitting its commit vote. Finality requires three matching hybrid commit votes and the prepare certificate. Changing view is monotonic and invalidates local old-round voting. Three signed change reports must agree on target view. Highest reported prepared certificate forces the next proposal; conflicting equal-height certificates are rejected. Without a reported prepared certificate the model permits either synthetic value. A genuine 2-2 PREPARE split can therefore move to a new round; it cannot be used to unlock old single-phase circulation votes. An old final certificate can coexist only with a matching safe value under the stated assumptions and correct honest behavior.

The tests exercise 2-2 prepare split, moving to a new round, refusal of duplicate reports and two votes, preservation of previously emitted commit votes when a certificate is withheld, tampered view report, refusal of obsolete-round commits and hybrid signature requirements. No persistent round locks, process separation, leader election/pacemaker, timeout policy, multi-height ledger integration, formal safety proof, exhaustive adversarial model checking, physical tests or regulatory certification. Never substitute this for the existing fail-closed persistent ledger. Next: specify a reviewed consensus protocol and durable exact signed state, add randomized and adversarial tests, integrate signed financial proposals only after safety review.

## Persistent round experiment

Linux `openPersistentPayRound` stores a journal bound to the single-height scope and authority pin, bounded at 256 events and 128 KiB per event. SQLite synchronous FULL / DELETE journal, BEGIN IMMEDIATE, no auto-provision on reopen. Every action replays the state machine, validates the original retained hybrid output, and commits the exact output before release. Identical semantic retries return the original signature bytes. Replay generates internal signatures which are discarded and never released. On ambiguous commit the handle halts. Hash chain and meta check detect ordinary corruption; they do not defend against same-user malicious rewrite, disk rollback or compromised keys. This is not independent node orchestration, formal BFT safety, real transaction integration, recovery from Byzantine storage, or a regulated payment mechanism. New tests exercise restart at preparation, view change, commit and final learning; stale/conflicting votes, corruption, withheld commit certificate. Results pending.

## Signed financial candidate experiment

`openFinancialRound` verifies actual hybrid payer signatures against the old circulation history, checks recipient identity, balance, nonce, root and admission-time expiry, and computes the hypothetical next balance. A new round domain binds the exact fixed candidate set, trusted membership and prior state. Existing persistent round stores can vote on these digests; a matching prepare and commit certificate projects the selected balance only. The experiment does NOT append to the old ledger, settle a payment, or establish a multi-height protocol. The candidate set is provisioned identically for this experiment: different sets/admission times constitute distinct scopes and must never be used as competing production decisions at one height. Admission time is a lab parameter rather than an external timestamp; there is no live expiration enforcement or abort protocol on delayed consensus. The raw round store is not a payment validator. Full network service integration, financial consensus review, durable global ledger migration and trusted time remain open. Tests include actual conflicting signed intents, 2-2 split, restart, next-round recovery, candidate tampering, mismatched certificate, insufficient signatures and conservation.

## Durable single-height settlement experiment

`openFinancialRoundLedger` binds one newly provisioned private SQLite database to the fixed financial scope and its preceding verified circulation state. Both hybrid quorum certificates must verify before any local fictional state change. The exact certificate and resulting root are committed atomically, verified on every read/reopen, and identical decisions return the original receipt without further debit. Reject different scopes, bad certificates, corrupt stored evidence, missing databases and provisioning over an existing directory. The prior single-phase ledger remains unchanged. No subsequent height integration, global exclusion between independent installations, trusted real-time expiry, remote orchestration or protection against complete disk rollback. The database relies on trusted local ownership; evidence is not encrypted and is synthetic only. Tests extend the signed 2-2 recovery through commit, restart, retry, conservation and corruption refusal. Results pending.

## Multi-height local chain experiment

`openRoundChain` introduces a separate genesis, payer transcript and state-root domain; old single-phase and single-height receipts are not imported. A trusted local coordinator retains exactly one immutable admission of up to four signed candidates per height, before consensus votes. Up to 32 heights, complete hybrid payer and prepare/commit certificate verification on replay, atomic SQLite commit and receipt retrieval, persistent pending admission, stale certificate idempotency, total-value conservation and nonce rejection. Existing independent round stores may be provisioned per height using the exposed round config. A new height can spend previously received funds. There is no distributed admission agreement: different coordinators or re-provisioned authority stores can create conflicting scopes; this experiment therefore remains local/trusted-coordinator only. No automatic abort for expired pending admissions, real-time finality, production payment, physical transport, formal BFT assurance or whole-disk rollback protection. Tests pending.

## Separate round authority service

`serve-pay-round-lab.mjs provision|serve PRIVATE_CONFIG` loads a private config containing the fixed chain config, committed history, admission, expected scope, local private key paths, authority pins, bearer token and loopback port. It independently verifies the full supplied prior history and candidate set on startup; the persistent round journal binds the exact scope. Fixed status/prepare/change-view/commit/learn routes via a separate domain-separated pay-round-lab Scattering profile. Each HTTP request/response is bounded at 32 KiB. This supports a 2-2 prepare split with empty prior prepared claims and three-signature certificates; large view-change reports containing several prior certificates may exceed the limit and are refused. One preprovisioned height per service, trusted provisioning/coordinator still required; no distributed admission, no live network deployment, no multi-height service automation. Four separate Linux processes and four native UDP links on one CI host exercise recovery after restart and local certified balance commitment. No physical hosts or real funds. Tests pending.

## Large view certificate transport

The dedicated round carrier retains the 32 KiB per-request limit and 16-operation epoch cap. A prepare containing a large view certificate can be uploaded in sequential canonical base64url chunks of at most 18,000 raw bytes, bounded to 98,304 total bytes, one volatile upload per authenticated witness and 120-second expiry. Exact offset, random upload ID and full SHA-256 digest required; partial or invalid input never reaches the consensus engine. Complete payload still undergoes all existing hybrid signature, round, scope and durable journal checks. No automatic retry, no public upload or file operation, no change to old mailbox/Pay carrier profiles. The complex recovery integration test hides the previous final certificate and carries three prepared claims via four separate services; tests pending. Epoch exhaustion or transfer timeout still stops progress; trusted provisioning and multi-height service orchestration remain separate work.

## Multi-height replica lifecycle

A fixed local authority now owns a chain bound to its public fingerprint and one persistent round journal per admitted height. Exact coordinator admission is revalidated against each replica's own history and freshness window; different pending admissions are refused. A newly admitted height may create its journal once, while missing pending journals on reopen block the replica (including interruption between the two durable stores). Learning verifies the full certificate and persists the round decision before advancing the local chain. A replica that missed a height may catch up from a certified record without signing, in order; pending admissions cannot be overwritten. Tests cover three transfers, four individual chains, restart, offline replica catch-up, insufficient signatures and missing journal refusal. This is a local API, not yet a network service or automatic peer discovery; the trusted coordinator is still required for admission, files rely on local custody, and disk snapshot rollback remains out of scope. No old lab database migration: owner binding changes the meta format; existing experimental chain directories are refused rather than silently migrated. Tests pending.

## Peer-sourced certified catch-up

Permanent replicas expose bounded record-begin/record-chunk reads of committed records only, with one volatile download, exact offsets, SHA-256, at most 96 KiB and expiration. `quantic-pay-replica-sync.mjs PRIVATE_CONFIG` runs one bounded pass against an explicit target and up to three distinct configured peer loopback links (network, authority pin, port, token). Status is an unauthenticated application-level hint within the configured carrier; only local independent verification of the received full financial certificate authorizes a state transition. No coordinator history is needed for this catch-up. Stop on ambiguous learning, root mismatch or exhausted batch. Tests replace coordinator-supplied catch-up with peer-sourced recovery over native UDP and local HTTP and exercise download bounds. No automatic timer, peer discovery, renewal or distributed admission; trusted coordinator still admits new transactions. Same-host tests pending.

## Quorum-gated admission experiment

Opt-in chain config `admissionPolicy: quorum-v1` creates a distinct genesis; legacy coordinator-only chains cannot be migrated or replayed into it. Before a scope can be admitted, at least three distinct pinned hybrid authority endorsements must verify against network, height, previous root, and candidate scope. Each replica persistently records one signed admission scope per height in its own SQLite transaction before releasing the vote. Reopen verifies retained locks; exact-scope retries return retained signatures. Only an endorsed scope can enter the existing prepare/commit protocol, including historical catch-up. A minority admission vote does not prevent learning a valid majority scope. Separate persistent replicas, at most one Byzantine key, no rollback/reprovisioning or key compromise assumed; the coordinator still proposes the candidate set and orchestrates communication. A 2-2 admission split can block permanently, with no timeout unlock. Admission recovery, automatic peer scheduling and epoch rotation remain open. The old ungated mode remains explicitly separate; no production use. Tests add conflicting admissions/restart/duplicate attack and exercise gated admission over native UDP. CI pending.

## Admission evidence recovery and epoch budgeting

A retained signed admission report can be read from an authority and independently verified against the current chain. Recovery groups distinct valid votes by scope and reconstructs an existing fresh 3/4 admission; duplicate signers fail. An expired quorum or 2-2 split remains blocked, including after restart. No new signature, no lock deletion and no automatic unlock. Recovery is a local coordinator API with authenticated report read route, not a view-change protocol for admission. The replica client counts attempted operations and preflights chunk uploads against the fixed 16-operation carrier epoch; conservative download preflight reserves the maximum number of chunks. Explicit fresh session provisioning after catch-up before a new gated payment in network integration test; no implicit retry or epoch renewal. Prior CI: 322 unit/application passes, 7 skipped, native Pay UDP step failed with a generic HTTP refusal in gated replica scenario; operation budget is a plausible cause, not confirmed by prior logs. New diagnostics include operation and HTTP status. Tests pending.

## V2 admission view-change experiment

The opt-in `round-v2` policy uses a new genesis incompatible with both older policies. At a height, the admission round has a single scope bound to network, prior root, height and authority membership, independent of competing candidate sets. Each proposed value is the separately verified financial scope digest. `openAdmissionRound` checks all payer proofs and admission freshness before prepare/commit, using a persistent round journal, with no v1 vote unlocking. Three matching hybrid prepare and commit votes are needed for admission. The financial chain verifies the full admission certificate at every replay/learn and then requires the separate financial prepare/commit certificate. Tests cover 2-2 prepare split and withheld prepared lock after restart, wrong scope, insufficient signatures, and subsequent local financial settlement. No production BFT proof, automatic admission pacemaker, delayed-expiry abort, durable cross-height admission lifecycle or remote wiring yet. Admission authority directories must be provisioned uniquely: raw generic stores can sign arbitrary digests, and independent provisioning/rollback must not be allowed. Expiry can still block progress. Tests pending.

## Configurable fixed committees (V3 local experiment)

Opt-in `round-v3` creates a separate genesis and explicitly domain-separated committee round scopes committing membership, size, calculated quorum, phase type and candidate set where applicable. Sizes 4 through 31 restricted to 3f+1, q=2f+1. No caller-defined threshold, no live membership rotation. Legacy modes retain four members and their existing scopes. V3 independently validates admission and financial certificates using the same committee; 16 members require 11 votes, 31 require 21. Local persistent round event cap 5 MiB, total journal cap 64 MiB; chain rows bounded to 1 MiB per serialized field. Tests include 7/16 persistent admission split and 16 retained locks, 31 member certificate with 20-vote/duplicate/foreign scope rejection. Slow replay and storage growth still need benchmarks; expanded certificates are NOT supported by existing 32 KiB frames / 96 KiB transfer limit or 16-call epoch. No remote V3 operation, no production claim, no independent physical infrastructure. New CI pending.

## V3 compact view certificate

Lossless dictionary encoding identifies repeated exact hybrid vote tuples and prepared certificate references in a view-change certificate. Committee verifier expands only the bounded structural representation, validates every required view-change signature and each distinct referenced prepared certificate, with original quorum/phase/scope and highest-prepared rules unchanged. No aggregation, truncation, or signature omission; legacy modes still reject compact representation. Local journals can retain compact prepare inputs. Tests use real ML-DSA-65 and Ed25519 signatures at 16 and 31 members, differently ordered prepared certificates, mutated references and signatures, duplicate reporters and conflicting candidates; persistent V3 admission test uses compact certificates. Compression ratio depends on duplicate evidence; worst-case distinct signatures are still large and may exceed transport bounds. Remote voting remains not wired; tests pending.

## Sixteen-service quorum experiment

`collectCommitteeVotes` checks unique expected authority pins, validates returned hybrid signatures for the exact phase/round/value and never counts failed calls or retries an ambiguous vote. Dedicated integration provisions and starts 16 independent Linux processes with distinct private keys, ports, tokens, journals and ledgers, stops five, collects 11 remote prepares/commits for admission and settlement, rejects 10 votes, then retrieves the record from a surviving authority and catches up the five restarted services. No fake time/freshness override or private-key signing by coordinator. Same host, not independent physical trust domains; malicious process fault injection and view change among all 16 still open. ## Five Byzantine synthetic signers

Adversarial test generates 16 independent hybrid key pairs and 11 durable honest replicas. Five lab signers bypass honest state deliberately to sign both competing values and falsely report no retained prepare QC. A 6-honest + 5-malicious withheld certificate intersects a later 6-honest + 5-malicious view in one honest lock; minority 5+5 conflicting votes fail. Admission and financial rounds both exercise restart, competing drafts/debits and required-value preservation. Eleven honest replicas then form a new financial quorum without malicious help, and settle one of two competing 75 EUR debits against 100 EUR synthetic balance. This is local persistent adversarial testing, not a formal proof or five independent malicious remote processes. CI pending.
