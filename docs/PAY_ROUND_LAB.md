# Experimental single-height view change

Separate synthetic protocol domain. Four fixed hybrid authorities; threshold three; at most one Byzantine authority; authenticated messages, fixed membership, and honest no-rollback state assumed. Two illustrative values only, not actual wallet transactions. This is an executable model, not a complete or proven production BFT implementation.

Prepare votes do not settle a transfer. A prepare certificate needs three hybrid votes in the same round. A commit vote requires a locally approved prepare and a verified prepare certificate; the authority retains that certificate while emitting its commit vote. Finality requires three matching hybrid commit votes and the prepare certificate. Changing view is monotonic and invalidates local old-round voting. Three signed change reports must agree on target view. Highest reported prepared certificate forces the next proposal; conflicting equal-height certificates are rejected. Without a reported prepared certificate the model permits either synthetic value. A genuine 2-2 PREPARE split can therefore move to a new round; it cannot be used to unlock old single-phase circulation votes. An old final certificate can coexist only with a matching safe value under the stated assumptions and correct honest behavior.

The tests exercise 2-2 prepare split, moving to a new round, refusal of duplicate reports and two votes, preservation of previously emitted commit votes when a certificate is withheld, tampered view report, refusal of obsolete-round commits and hybrid signature requirements. No persistent round locks, process separation, leader election/pacemaker, timeout policy, multi-height ledger integration, formal safety proof, exhaustive adversarial model checking, physical tests or regulatory certification. Never substitute this for the existing fail-closed persistent ledger. Next: specify a reviewed consensus protocol and durable exact signed state, add randomized and adversarial tests, integrate signed financial proposals only after safety review.

## Persistent round experiment

Linux `openPersistentPayRound` stores a journal bound to the single-height scope and authority pin, bounded at 256 events and 128 KiB per event. SQLite synchronous FULL / DELETE journal, BEGIN IMMEDIATE, no auto-provision on reopen. Every action replays the state machine, validates the original retained hybrid output, and commits the exact output before release. Identical semantic retries return the original signature bytes. Replay generates internal signatures which are discarded and never released. On ambiguous commit the handle halts. Hash chain and meta check detect ordinary corruption; they do not defend against same-user malicious rewrite, disk rollback or compromised keys. This is not independent node orchestration, formal BFT safety, real transaction integration, recovery from Byzantine storage, or a regulated payment mechanism. New tests exercise restart at preparation, view change, commit and final learning; stale/conflicting votes, corruption, withheld commit certificate. Results pending.

## Signed financial candidate experiment

`openFinancialRound` verifies actual hybrid payer signatures against the old circulation history, checks recipient identity, balance, nonce, root and admission-time expiry, and computes the hypothetical next balance. A new round domain binds the exact fixed candidate set, trusted membership and prior state. Existing persistent round stores can vote on these digests; a matching prepare and commit certificate projects the selected balance only. The experiment does NOT append to the old ledger, settle a payment, or establish a multi-height protocol. The candidate set is provisioned identically for this experiment: different sets/admission times constitute distinct scopes and must never be used as competing production decisions at one height. Admission time is a lab parameter rather than an external timestamp; there is no live expiration enforcement or abort protocol on delayed consensus. The raw round store is not a payment validator. Full network service integration, financial consensus review, durable global ledger migration and trusted time remain open. Tests include actual conflicting signed intents, 2-2 split, restart, next-round recovery, candidate tampering, mismatched certificate, insufficient signatures and conservation.
