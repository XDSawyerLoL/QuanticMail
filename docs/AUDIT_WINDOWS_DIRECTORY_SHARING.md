# Windows directory rename regression
CI 44938410249 / 136950055693 reproduced successful rename of the queue while an attribute-only directory handle was open. Windows share-mode checks are not sufficient on metadata-only handles. Request FILE_LIST_DIRECTORY in addition to FILE_READ_ATTRIBUTES and existing READ_CONTROL, keeping FILE_SHARE_DELETE absent. All traversed directories must be opened successfully or the operation refuses. Added test of ancestor/root rename as well as the existing queue, concurrent guard and spent-epoch tests. The fix is pending real Windows CI; no assertion of success before then. On a restrictive ancestor ACL this may refuse operation rather than bypass protections.
Linux parallel run 44938404617 reported counts [4,4,4,3] after a successful 3-of-4 operation. The other Linux run succeeded. No threshold or test expectation was weakened; the lagging witness requires investigation before asserting resilience.
