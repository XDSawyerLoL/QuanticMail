# Native isolation and release boundary
The isolated Go RC1 laboratory, supplied separately, is not wired to the production desktop nor committed as source in this branch. Native signing uses a TPM provider on Windows only; the encryption key is ephemeral software in the isolated process. Linux uses explicit synthetic software test mode. No old private key import, no web bridge, no persistent key enrollment. The lab integrates the existing native-enrollment manifest validator with two local processes and tests encrypted challenge recovery; it does not enforce ECDH proof or trusted UI consent in production. The 26 local tests include 8 inherited enrollment tests; Windows physical hardware untested. No production account accessed.
Release workflow additionally requires main, valid Authenticode and exact SHA-256 of the DER publisher certificate set via QUANTIC_WINDOWS_SIGNER_SHA256 repository variable. Unset or unexpected pin blocks publication. Establish this variable through trusted out-of-band verification before enabling a signed release. No certificate generated, signing secret configured, release published, or end-user updater implemented. Rotation requires separately authorized pin update. CI for the new workflow still required.
