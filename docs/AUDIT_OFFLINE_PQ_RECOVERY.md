# G01/G13 — offline PQ recovery verification
Node 24/OpenSSL native primitive process (not the Go quorum broker). Explicit local Linux terminal only, no HTTP/renderer/IPC endpoints, no password command-line or environment argument. Run `node --experimental-transform-types scripts/verify-offline-pq-recovery.ts /private/archive.qma /private/pins.json [/private/historical-fixture.json]`. Files owner-only, regular, bounded; no final symlink. Pins must be independently recorded from trusted original identity/device (full SHA256 of DER SPKI root, device classical encryption, ML-KEM and ML-DSA public keys, exact strong canonical address and deviceId). Never generate them from the archive being checked. Optional historical fixture consists of existing hybrid context/envelope plus independently recorded SHA256 of the original JSON payload; not a fresh proof of sender identity. The workflow verifies classical encryption key pair, address binding, exact PQ public/private pairs, local randomized ML-KEM encapsulation/decapsulation and domain-separated ML-DSA sign/verify, optionally a historical hybrid ciphertext. Only boolean results leave the process. No generic signing API, returned secrets, live authentication, prekey resurrection, restore, deletion or downgrade. 
A local process still holds historical private values temporarily in managed memory; JS strings cannot be reliably zeroized, and OS-level compromise remains a threat. No claim of Go native isolation or quorum; actual live operations remain blocked on broker integration and signed authority checks. Requires native algorithms at runtime, fails closed otherwise. Tests use real PQ keys and reject wrong independent pins, unrelated secret, wrong historical digest and routing.
