# Local native desktop workflow (G01, G12)
Run from a Linux terminal: npm run desktop:native-lab. This is a separate execution mode of the existing Electron application, not a remote-page bridge. It never creates the remote BrowserWindow and exposes no IPC handlers to web content. Native file-selection and message dialogs select a private lab configuration and exact static envelope or enrollment challenge, prompt for confirmation, then call the pinned existing Go broker via the Node controller. The broker still requires its own controlling-terminal password and consent, and fresh quorum. No fallback. 
Inputs are regular local files, no final-component symlinks, maximum 32 KiB; config owner and permissions checked. Use trusted local directories, no attacker-controlled installation or config. Plaintext is displayed through an OS dialog and is not logged or saved by this workflow. Trusted main process and OS UI can see it; no claim of memory protection. Display explicitly marks sender unverified. Enrollment proof can be saved only into a new private file; a failed operation can leave an incomplete file. 
Requires independently provisioned synthetic native vault, compact registry, four witnesses and pinned broker executable; no public account migration, live relay fetch/ack, historical keys recovery, PQ native operations, Windows runtime or production UI support. A consumed replay right may prevent retry after interruption; do not delete input. Desktop dialog tests exercise workflow via injected dialog/controller, not the real graphical Electron runtime. Keep historical identity and mail intact. No production deployment.
