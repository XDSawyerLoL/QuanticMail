# Native migration — non-destructive inventory
Audit P0, preparatory implementation, not cutover. The current root identity and manifest format bind the canonical address to the original signing key. A new native linked device does not replace that trust root. Existing browser secrets, local prekeys, PQ secrets, mail, contacts, outbox and pending pairs must be explicitly accounted for. The v2 identity backup includes the historical root classical key pair, not all these classes; old keys already exposed cannot be made secret retroactively.

The vault page now shows a read-only snapshot of identity and store counts in one IndexedDB transaction; no secret or address in the inventory result, no network/export, no deletion. Database initialization may create absent stores. Count does not establish recoverability, validity or exclusivity. No live native bridge or automatic import added; old identities continue to operate. 

Gates: local native key possession (both signing and decryption); signed exact enrollment in real registry plus durable re-read; actual authenticated delivery and retrieval; recovery test with historical ciphertext and PQ material; independent local approval and durable cutover across concurrent tabs; root key rotation or protected offline root path, no downgrade; revoke legacy device and credentials only after verified recovery and explicit authorization. Keep original data until these gates pass. Never treat user-supplied flags, inventory counts or lab enrollment as proof of migration.
