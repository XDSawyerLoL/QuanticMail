# QuanticMail V0.3 — Production mail server

## Production topology

QuanticMail deliberately separates the public webmail hostname from the SMTP/JMAP server hostname.

Use a domain you actually control. The examples below use `example.com`; a brand-domain candidate can be substituted later without changing the architecture.

- `mail.example.com` — QuanticMail web application
- `mx.example.com` — Stalwart mail server, JMAP discovery, SMTP, submission and IMAP
- `example.com` — mail domain used for addresses such as `valentin.hernandez@example.com`
- VPS PTR/rDNS — points the public VPS IP back to `mx.example.com`

This avoids competing for HTTPS port 443 between the QuanticMail web application and Stalwart while keeping standard mail protocols directly reachable.

## Required DNS records

Replace `VPS_IP`, `example.com` and the generated DKIM values with production values.

```dns
mx.example.com.              A       VPS_IP
example.com.                 MX 10   mx.example.com.
example.com.                 TXT     "v=spf1 mx -all"
_dmarc.example.com.          TXT     "v=DMARC1; p=none; rua=mailto:dmarc@example.com; adkim=s; aspf=s"
```

DKIM must be copied from Stalwart after the domain is provisioned. Do not invent or pre-generate the public key in Git.

After validation, DMARC can move gradually from `p=none` to `p=quarantine`, then `p=reject`.

## VPS prerequisites

Recommended baseline:

- Ubuntu LTS
- dedicated public IPv4 address
- Docker Engine + Docker Compose plugin
- TCP 25 open for server-to-server SMTP
- TCP 443 open for Stalwart HTTPS/JMAP
- TCP 465 and 587 open for authenticated submission
- TCP 993 open for IMAPS compatibility
- TCP 4190 optional for ManageSieve
- firewall default-deny for all other unsolicited inbound ports

Hostinger VPS supports PTR configuration in hPanel. Set the VPS PTR to the production mail hostname (for example `mx.example.com`) only after its `A` record resolves to the VPS public IP.

## Production environment

Create an environment file outside source control with at least:

```env
MAIL_SERVER_HOSTNAME=mx.example.com
NEXT_PUBLIC_MAIL_DOMAIN=example.com
JMAP_SESSION_URL=https://mx.example.com/.well-known/jmap
SESSION_SECRET=<production secret, 32+ random bytes>
```

The production Compose file consumes `MAIL_SERVER_HOSTNAME` and refuses to start without it.

## Stalwart first-run values

Use the web setup wizard after the container is started:

- Server hostname: the value of `MAIL_SERVER_HOSTNAME`
- Default email domain: the domain you own
- Automatic TLS: enabled
- DKIM generation: enabled
- DNS management: manual initially
- Logging: console when running in Docker

Once the domain exists in Stalwart, use the generated DNS zone output as the source of truth for DKIM and the remaining mail-discovery/security records.

## First mailbox

Provision the first account only inside Stalwart administration, never in source control. Example:

`valentin.hernandez@example.com`

Use a long unique password and enable stronger authentication when the production identity layer is added.

## QuanticMail web configuration

The deployed Next.js application uses:

```env
NEXT_PUBLIC_APP_NAME=QuanticMail
NEXT_PUBLIC_MAIL_DOMAIN=example.com
JMAP_SESSION_URL=https://mx.example.com/.well-known/jmap
SESSION_SECRET=<production secret, 32+ random bytes>
```

Never expose `SESSION_SECRET`, mailbox passwords, DKIM private keys or Stalwart administrator credentials to the browser or GitHub.

## Validation checklist

Before sending real business mail:

1. The mail hostname resolves to the VPS IPv4 address.
2. VPS PTR resolves back to that same mail hostname.
3. Forward-confirmed reverse DNS matches in both directions.
4. TLS certificate is valid for the mail hostname.
5. MX points to the mail hostname.
6. SPF passes.
7. DKIM passes with the Stalwart-generated selector.
8. DMARC reports arrive at the reporting mailbox.
9. SMTP port 25 is reachable externally.
10. Submission on 587 requires authentication and TLS.
11. No open relay is possible.
12. Gmail and Outlook test messages arrive without authentication failures.

## Hostinger-specific note

Hostinger currently documents that SMTP port 25 is not blocked on VPS plans, but outbound sending is limited to roughly five messages per minute. That is sufficient for an initial corporate mailbox, not a bulk-mail platform.
