# Windows native provisioning and replay journal — staged laboratory
Adds an explicit --provision-windows-pq-storage-lab DIRECTORY CONTROLLER_PUBLIC_KEY QUORUM_PIN CANONICAL_ADDRESS command only in Windows CGO+pqopenssl builds. An actual attached Windows console is required, not stdin or environment credentials. Console echo is disabled for each passphrase and restored; an explicit confirmation and distinct passwords are required. The lab accepts printable ASCII only. Uses the existing compact-quorum classical key format and bound PQ sidecar format. Provisions a new protected NTFS directory and writes both encrypted stores plus a bound journal using exclusive creation. Only public keys and pins are returned. No enrollment or migration is performed. Partial provisioning retains the original directory and cannot be silently overwritten.
Windows replay opens the same hash-chain format on an ACL-validated, exclusive write-through file handle with directory handles held open, and reuses existing hash-chain parsing and flush. A synthetic child test flushes a record and exits without explicitly closing; reopening must reject replay and partial records. This does NOT establish power-loss durability or rollback protection; remote quorum integration, result-cache custody, controller/authority file custody, interactive desktop tests, and packaging remain outstanding. No live broker enablement: the previous Windows portable broker gate remains closed.
