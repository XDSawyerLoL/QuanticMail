# Identity Vault security hardening — draft, no production activation
Base 9aa0d89. Seven risks tracked separately:
1. Critical: private JWK and bearer token in browser IndexedDB. Added Windows TPM capability probe only, NO migration or native signing service. A native service must generate nonexportable device keys, enforce local user approval, scope and replay-resistant requests, never export root material into a renderer. Existing identity migration needs separately verified backup/recovery, new key enrollment/revocation and proof of compatibility; existing root P-256 fingerprint cannot be silently replaced.
2. Web compromise: Electron sandbox/WebSecurity, deny permission requests/checks and webview, restrict windows and navigations; arbitrary redirects prevented. Web CSP, locally trusted UI, supply-chain exposure and origin compromise remain; stage without breaking web flows.
3. Backup: PBKDF2 SHA256 600000 for new exports, 14-char minimum, legacy import retained (100000–2000000 iterations), input bounds and key-pair consistency verification. Argon2id versioned migration and recovery entropy still needed. Existing backups remain weak if password weak; re-export after validation. No cloud recovery.
4. Electron navigation: exact HTTPS origin rather than string prefix; no external launch on redirect; only explicit portal navigation may launch external. Windows interaction tests pending.
5. API: exact origin comparison, explicit HTTPS configured origins via QUANTIC_TRUSTED_ORIGINS. Origin check is not authentication. Existing proxy CORS intentionally unchanged pending compatibility audit: bearer APIs must have per-route object authorization, nonce, device/manifest checks, bounded request size. No claim of completed IDOR/BOLA review.
6. Local rate limit: bounded map, monotonic deadline and cleanup. Existing process-local limitation remains; deploy atomic shared SQL counters with authenticated identity/device and trusted network attribution; verify multi-instance restart and flood behavior. No automatic new limits on mail endpoints.
7. Release: manual workflow, no unsigned installer publication, no overwrites, SHA256 sidecar. Authenticode signing provisioning and publisher certificate pinning remain required; reproducible dependency lockfile/pinned Actions/attestation/dependency audit needed. This draft intentionally blocks unsigned desktop publication and is not a complete supply-chain solution.
Tests: node --experimental-transform-types --test tests/identity-vault-hardening.test.mjs (requires installed runtime). Full CI and Windows TPM probe require real systems. All production gates remain closed. Scattering RC5 stays experimental and is not merged into the actual identity transport.
