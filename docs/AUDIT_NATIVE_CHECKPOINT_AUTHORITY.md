# Independently attested native identity checkpoint
This adds a usable offline/local authority issuer for the existing durable standalone relay V3 state file, not an automatic production authority service. Run Node 24: node --experimental-transform-types scripts/issue-native-checkpoint.mjs --independent-authority /absolute/relay-state.json /absolute/policy.json /absolute/request.json /absolute/authority-key.pem. All inputs owner-only regular POSIX files, bounded and opened no-follow. Each independently provisioned Ed25519 authority checks a fresh persisted relay snapshot (max 30 seconds), exact independently approved identity/device/manifest/profile sequences and digests and both identity root pins, verifies real signatures and active hybrid-required device, then signs a domain-separated nonce-bound checkpoint valid at most 15 seconds. Policy is an array of explicit checkpoint fields plus active:true; manual trusted policy updates required. Request is address,deviceId,nonce (32 random bytes hex),expires. Client requires 3 of 4 distinct pinned Ed25519 keys and exact matching signed checkpoint, verifies both identity signatures and native mail signatures using existing bridge. Expired, missing, divergent, forged votes fail closed. No trusting network-provided roots, no signing in relay, no private key export. Authority key is classical Ed25519; PQ identity proofs still independently checked. Authenticity of current policy and state snapshot, separate fault domains, policy monotonic update, trusted clocks, rollback resistance and remote distribution are deployment prerequisites. savedAt alone does not prove freshness against a malicious relay. Expired idle state intentionally refuses until actual fresh durable snapshot available. Not automatic account migration, live delivery, or production release. Synthetic test uses actual V3 state shape and distinct keys; CI pending.
