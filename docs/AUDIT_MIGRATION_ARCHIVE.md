# Migration recovery archive (.qma)
Separate from V1/V2 root-only .quantic-vault. Bounded consistent IndexedDB snapshot (six stores) with identity, historical private keys, PQ material if present, prekeys including claimed/expired states, pending pairing, messages, contacts, outbox. Existing top-level identity and pending bearer tokens deliberately excluded. AES-256-GCM with random 96-bit IV, PBKDF2-SHA256 600k and independent random 128-bit salt, separate AAD domain. Limits: 10,000 rows per collection; 16 MiB serialized payload. No truncation. The UI performs a roundtrip before offering the download and allows rereading the actual file without database writes.
This is an encrypted export of sensitive historical data, NOT a validated live restore, identity authority, proof of key validity or native isolation. Password possession and AEAD integrity alone do not prove author authenticity or freshness; expected canonical address is a user check, not a trusted root pin. Archive contents are not trusted for registration or sending. No auto replay/resume of old prekeys, pending devices or outbox; server authority must be reconciled and tokens freshly authorized. Backups increase exposure of historical secrets and can weaken forward secrecy if retained. Store offline, separately from password, and retain only as necessary. A compromised web origin/OS can see plaintext; JS memory wiping is best effort. Tests prove classical historical root/prekey decryption with synthetic fixtures, wrong password/address and tampering rejected; real account recovery, PQ secret operation and OS-specific native import remain gates. Never erase any existing data based on this archive.

Follow-up: trusted local Node 24 migration-proof-node.mjs accepts encrypted archive, password, exact historical canonical address and independently obtained original P-256 signing SPKI SHA-256 pin. Checks the signed historical manifest, exact archived device keys, actual root/device signatures and ECDH, retained prekey possession, ML-KEM and ML-DSA key pairs, and pending device material if present. Mismatched root, substituted private keys, modified manifest and substituted PQ keys refused. No private material or account identifier in report; no network or database mutation, no automatic fallback for incomplete legacy identities. This is a dry-run key continuity check, not proof of freshness, all historical messages, prekey authorization, live restore or deletion. Pending CI; no real account processed.

Historical prekey verification now requires the original device signature on each exact prekey record (including dates and scope), and runs an actual synthetic legacy envelope encryption/decryption challenge for the archived device key and each retained prekey. Altered expiry or replaced key pair without an original device signature are refused. Claimed/expired keys never become active. The archive contains already-decoded local messages and outgoing envelopes meant for other recipients; the synthetic challenge does not prove completeness, authenticity of archived plaintext, remote pending ciphertext recovery, or successful live migration. No destructive cutover enabled.

The local dashboard exposes a read-only MigrationCheck action with a file picker and independently supplied historical address and root pin. Bundled Node verifies the encrypted archive with an interactive non-echoed password; password is not in argv, config, logs or the GUI. Report contains only counts and verification statuses. Managed memory cannot guarantee erasure. No upload, account mutation, live migration, automatic enrollment or deletion. Existing cryptographic tests cover synthetic archive checks, not the real interactive Windows console. CI validates script syntax and rejection of missing inputs.

Source-side reconciliation compares the archive against a fresh read-only IndexedDB snapshot after successful decryption, ignoring live bearer rotation. Compare identity and pending pairing, then every message, contact, prekey and outbox record by unique canonical key and content, irrespective of row order. Report only counts (missing, changed, extra) and equality statuses; duplicate rows or identity mismatch are refused. No restore or deletion is authorized; results represent only the captured transaction and do not freeze concurrent writers or prove remote queue completeness. No real account was touched.

The legacy source UI now displays the independently derived SHA-256 SPKI fingerprint of its public historical ownership key, to record separately before importing an archive on Windows. WebCrypto and Node crypto cross-check the identical fingerprint in CI. The helper refuses private or malformed JWKs. This reference does not authenticate an already compromised source or authorize live migration.
