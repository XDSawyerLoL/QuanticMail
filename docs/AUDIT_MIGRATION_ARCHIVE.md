# Migration recovery archive (.qma)
Separate from V1/V2 root-only .quantic-vault. Bounded consistent IndexedDB snapshot (six stores) with identity, historical private keys, PQ material if present, prekeys including claimed/expired states, pending pairing, messages, contacts, outbox. Existing top-level identity and pending bearer tokens deliberately excluded. AES-256-GCM with random 96-bit IV, PBKDF2-SHA256 600k and independent random 128-bit salt, separate AAD domain. Limits: 10,000 rows per collection; 16 MiB serialized payload. No truncation. The UI performs a roundtrip before offering the download and allows rereading the actual file without database writes.
This is an encrypted export of sensitive historical data, NOT a validated live restore, identity authority, proof of key validity or native isolation. Password possession and AEAD integrity alone do not prove author authenticity or freshness; expected canonical address is a user check, not a trusted root pin. Archive contents are not trusted for registration or sending. No auto replay/resume of old prekeys, pending devices or outbox; server authority must be reconciled and tokens freshly authorized. Backups increase exposure of historical secrets and can weaken forward secrecy if retained. Store offline, separately from password, and retain only as necessary. A compromised web origin/OS can see plaintext; JS memory wiping is best effort. Tests prove classical historical root/prekey decryption with synthetic fixtures, wrong password/address and tampering rejected; real account recovery, PQ secret operation and OS-specific native import remain gates. Never erase any existing data based on this archive.
