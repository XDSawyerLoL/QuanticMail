# Windows encrypted storage — staged native laboratory
Windows CGO+pqopenssl build now contains native NTFS file-custody primitives using Win32 handles: a unique directory with protected DACL granting only the current user SID and SYSTEM, exclusive non-overwriting writes, FILE_FLAG_WRITE_THROUGH and file flush, strict owner/ACE checks on the opened file, no hardlinks or reparse points, no network/UNC, alternate data streams or ambiguous DOS paths. Ancestor handles are held without delete sharing while operating. Explicit lab path syntax ASCII only; trusted local user, OS and private parent environment required. No protection against malicious same-user processes or administrators. Uses the existing AES-GCM/PBKDF2 encrypted classical and PQ sidecar formats, including existing independent key bindings; Linux encryption path refactored to reuse the same codec. No new crypto scheme.
CI adds synthetic persisted classical keys and ML-KEM/ML-DSA reopening plus real cryptographic operations, wrong password/pins, altered ciphertext, existing file, broad ACL, hardlink, junction and ADS rejection. Pending until CI confirms.
Not yet wired into the existing broker, GUI, terminal or journal. The existing Windows portable provider remains fail-closed; Windows file flush is not a proven parent-directory durability/atomic commit guarantee. Never use a live account, ship an installer or acknowledge a message based on this storage experiment. Next: Windows console consent, verified journal/checkpoint storage and recovery semantics, trusted Node controller/authority file custody, independent physical-machine tests and complete package review.
