# Two-host Scattering mailbox bridge (laboratory only)
Added distinct client and relay endpoints with fixed loopback HTTP routes (send, pull, ack, recover); an existing native mailbox client can target the client's loopback port. Relay side forwards only to its configured local native mailbox service. Request/response JSON frames travel through the existing fixed 168-byte reliable Scattering cell implementation with separate directional HKDF keys and fixed dual-proof cadence. No direct remote HTTP, arbitrary proxy destination, new signature or automatic HTTP replay. Transport ACK is volatile; actual relay status is returned separately and existing mail protocol retains its own durability and authentication checks. Each epoch is explicit, limited to 16 sequential operations, uses a fresh independent 32-byte random secret and a fresh independent 32-byte random epoch, and has a durable consumed marker in a private local state directory. Marker rollback/cloning is not protected; never reuse or automatically renew an epoch, never share secrets over ordinary HTTP. No production exposure.
 
On each Linux host create private empty queue directory and separate persistent private state directory (0700; absolute non-symlink paths); run the keyless native pacer targeting the other host's UDP sink, and its native sink forwarding to this host's fixed local UDP receive port. Start pacers and sinks independently before the application, so process failure does not terminate cover. Use a private 0600 configuration file on each host with fields labOnly:true, role:"client" or "relay", secretHex, epochHex, queueDir, stateDir, recvPort, httpPort. Provision identical secret/epoch out of band from independent randomness, different queue/state directories per host. On client httpPort is the local listener; relay httpPort is the actual local native mailbox port. Run node scripts/serve-native-scattering.mjs --two-host-mailbox-lab /absolute/private-config.json. Example synthetic configuration must not be used with real credentials. The two native programs stay alive independently of the bridge. New epoch requires controlled reprovisioning and fresh empty queues; no claim that epoch changes conceal timing or avoid a gap.

CI exercises real native pacers and sinks on localhost, all four fixed HTTP operations against a synthetic upstream, a larger request, unknown route refusal and repeated-epoch refusal. Does not prove real SMTP/mail delivery, independent physical paths, NAT reachability, resilient WAN timing, remote authority lookup confidentiality, application-level replay resistance beyond existing mailbox protections, or indistinguishability. No automatic restart/rekey, no Windows configuration-file ACL support. A compromised local process can read secrets. WAN experiment and full real relay plus authorities are outstanding. Do not use live accounts.
