# Windows Scattering transport port (laboratory)
Explicit native guard holds validated NTFS directory handles, refuses non-empty queue and writes a unique spent-epoch marker before allowing the Node bridge to start. Queue ACL uses owner/SYSTEM inheritable ACEs for opaque encrypted spool files; separate state and config use existing strict ACL. The guard closes the bridge on unexpected exit. Native pacer and sink remain independent. Spent marker rollback/cloning and power-loss durability remain unsolved, no automatic rekey. Same-user/admin compromise is outside the model. Windows endpoint uses the existing cell stream and fixed loopback mailbox routes. Tests added for attempted queue rename, epoch reuse and nonempty queue. No physical path or real-account test.
Create a new transport directory via Vault-PQ-lab.exe --windows-scattering-create-lab ABS_DIR (not the identity vault). A trusted operator writes separately provisioned synthetic config through stdin via --windows-scattering-config-lab ABS_DIR, no command-line secret. Config fields match Linux, queueDir and stateDir are direct children queue and state. Launch independent native pacer and sink as documented, and node scripts/serve-native-scattering-windows.mjs ABS_BINARY TRUSTED_SHA256 ABS_DIR. Client/relay loopback endpoints only. No direct remote HTTP fallback. Windows desktop integration and Windows-to-Linux network test remain distinct validation steps.
