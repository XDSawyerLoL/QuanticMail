# Fictional central settlement and interruption recovery

New isolated Linux/Node 24 laboratory, no provider integration or redeemable currency. A wallet starts with 10000 synthetic cents, a demonstration merchant and person each with zero. An atomic SQLite transfer records the unique nonce, canonical digest, reference, recipient and amount. Balances are derived from the transfer set; total synthetic value remains constant. Independently pinned four hybrid witness keys and a fresh three-of-four signed matching history are mandatory before the simulated settlement. Existing matching nonces return the original receipt, not another debit. Read-only lookup supports recovery after a lost response or process restart. This is a single-wallet model, not a distributed central bank or multi-wallet payment service; no refund, real settlement, or live account identifiers. Local DB custody, backup and rollback security are not certified.

Read-only interruption classification for a known pending local nonce checks the complete local proof set and, if that does not match, the set excluding that one exact proof against fresh independently signed checkpoints. A prior-set match is evidence of the quorum's observed state, not proof no minority witness accepted it or that a retry is safe. No deletion, automatic replay or re-signing; unresolved sessions remain closed. Reopening the native flow still requires fresh exact quorum. No remedy for partial distributed writes has been authorized or implemented.

Regression extends the four separate witness service tests, including optional four native Scattering links: quorum failure, offline dictionary preview, simulated settlement, conservation, persistent restart, idempotent same nonce and read-only recovery. Windows native console and physical five-machine tests remain separate.
