# Quantic Network V0.9 — Multi-device certificates

V0.9 lets one canonical Quantic identity operate on several devices without copying the master identity signing private key to every device.

## Roles

### Root device

The root device holds:

- the identity ECDH encryption key pair;
- the master ECDSA identity signing key pair;
- its own Render authentication token;
- the canonical identity such as `sansa~4f82a19c2d@quantic`.

The master signing private key is the authority that can authorize another device.

### Linked device

A linked device creates locally:

- its own ECDH P-256 encryption key pair;
- its own ECDSA P-256 device signing key pair;
- its own random Render authentication token;
- a device ID derived from its encryption public key.

It does not receive the master identity signing private key.

## Device request

A fresh device generates a `.quantic-device-request` JSON document containing:

- the canonical identity it wants to join;
- device ID;
- device label;
- device encryption public key;
- device signing public key;
- creation timestamp.

Private keys and the device auth token stay in local IndexedDB.

## Root-signed certificate

The root device checks that the request targets its own canonical identity and signs a deterministic certificate message containing:

- canonical address;
- human handle;
- master identity fingerprint;
- root encryption public key;
- master signing public key;
- linked-device ID and label;
- linked-device encryption public key;
- linked-device signing public key;
- certificate issue time.

The resulting `.quantic-device-cert` contains the public payload plus the ECDSA P-256 signature.

## Registration after relay restart

A linked device can submit its certificate and a fresh/current local auth token to `/api/quantic/devices/register`.

The relay verifies:

1. the canonical identity fingerprint matches the supplied master signing public key;
2. the linked-device ID matches its encryption public key;
3. the certificate payload is internally consistent;
4. the certificate signature verifies against the master identity signing public key.

Because authorization is cryptographic, the relay does not need a permanent paid database to remember that authorization between restarts. The linked device retains the certificate locally and can present it again.

## Per-device delivery

Directory resolution returns a public device list. A sender encrypts a separate copy of the plaintext payload for each listed device encryption public key.

The relay stores queues under a key equivalent to:

`canonical-identity # device-id`

A device authenticates with its own token and can pull only its own queue.

Delivery receipts are likewise routed back to the exact sender device that created the encrypted delivery.

## Local outbox

For a recipient with N devices, one visible sent message can produce N encrypted outbox items. Every encrypted device delivery has its own message ID and remains in IndexedDB until its receipt returns.

This keeps V0.6 store-and-forward durability while extending it to multiple devices.

## What V0.9 does not yet solve

- device revocation lists that survive relay restarts;
- QR-code / proximity pairing;
- synchronized readable message history between the user's own devices;
- automatic removal of an old lost device from other users' cached device directories;
- background push notifications when the web app is closed.

These are intentionally separate protocol layers. V0.9 establishes the core cryptographic device authorization and independent encrypted delivery model first.
